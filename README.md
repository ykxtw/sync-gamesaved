# 云档 v2.3.2 —— 游戏存档 启动器（局域网同步/备份）

**图形启动器**：选游戏 → 一键开玩，开玩前把存档从 NAS 拉到本地，退出后推回 NAS，推送前自动备份将被覆盖的网络文件。命令行版保留（计划任务/脚本用）。

## 快速开始

```bat
:: 已带打包产物，直接用：
dist\云档.exe          ← 双击启动器（图形界面）
dist\云档-cli.exe      ← 命令行版（可选）

:: 首次使用：启动器里点“+ 添加游戏”，填好程序路径与目录对即可
:: 所有配置保存在与 exe 同目录的 云档.toml，界面内可随时改
```

源码运行 / 重新打包：

```bat
py -m pip install psutil customtkinter pillow
py 云档GUI.py                 # 直接跑启动器
build.bat                     # 打包 dist\云档.exe + dist\云档-cli.exe
```

> 首次运行 exe 可能被杀软误报，添加信任即可。

## 启动器界面

```
┌──────────────────────────────────────────────────┐
│ 云档启动器                    [统计] [全局设置]   │
├────────────┬─────────────────────────────────────┤
│ 游戏库      │  [封面] 游戏名                       │
│ ▣ 阿尔法    │  模式/备份/等待进程/目录对/排除       │
│ ▣ 贝塔      │  状态：就绪 / 游戏运行中 已 12:34     │
│ ▣ 伽马      │  [▶ 开始游戏] [仅同步] [打开存档目录] │
│ + 添加游戏  │  [编辑] [删除]                       │
│             │  会话日志（实时滚动）                 │
└────────────┴─────────────────────────────────────┘
```

- **游戏库卡片**：名称（大号）+ 模式 + 累计/本周游玩时长（小字，可选封面图）
- **▶ 开始游戏**：预检 → 锁 → 恢复 → 启动并跟踪进程树 → 退出后备份+推送 → 写会话标记 → 记时长
- **统计按隐藏ID归属**：每个游戏自动带一个隐藏ID（配置文件里 `id = …`，勿改勿删），改名不丢统计；旧版统计 CSV 首次启动自动升级并按名称盖 ID，历史数据不丢
- **会话中**：状态条显示阶段与实时游玩时长；可“提前结束并同步”（相当于玩完了）或“中止会话”（不推送）
- **编辑对话框**：名称、程序（**选择程序…** 浏览按钮）、启动参数、工作目录、封面（**选择图片… / 从图标生成**：直接提取 exe 内嵌图标，最高 256×256；选完程序若封面为空还会自动生成）、等待进程、保留份数、模式（带说明）、**目录对可增删行+浏览选择**、排除规则
- **全局设置**：备份保留份数、启动超时、网络等待；也可一键打开配置文件高级编辑
- 固定位置：`云档.toml` / `云档.log` / `云档统计.csv` / 封面缓存 `covers\` 都在程序目录下
- 引擎的交互确认（镜像缺标记、锁被占、归档比本地旧等）都会弹窗询问，不会在界面卡死

## 三种模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `timestamp`（默认） | 两端各自保留最新文件，**从不删除** | 大多数情况，最安全 |
| `mirror` | 两端完全一致，删除多余文件 | 想与 NAS 严格一致；有会话标记保护 |
| `archive` | 网络端存 zip 快照（保留 N 份），本地恢复最新快照 | 想要完整历史版本 |

## 命令行版（云档-cli.exe / py 云档.py）

```
云档-cli.py                     单游戏直接开始；多游戏出菜单
  -g, --game 名称              按名称选择（模糊匹配）
  --sync-only                 不启动游戏，仅双向同步（日常备份）
  --dry-run                   演练模式：只显示将发生什么
  --list / --stats / --wizard
  -c, --config 路径           指定配置文件（默认 同目录\云档.toml）
  --no-pause                  结束后不暂停（计划任务/脚本调用）
```

**退出码**：`0` 成功 · `1` 同步失败 · `2` 启动失败 · `3` 配置错误 · `4` 预检失败 · `5` 用户取消 · `9` 未预期错误

## 配置文件（云档.toml）

完整示例见 `云档.example.toml`。所有字段都能在启动器界面编辑；要点：

- 路径用**单引号**包裹（TOML 字面量），反斜杠不用转义
- `process = []` 留空自动跟踪启动的进程树（含所有子孙进程）；启动器常驻托盘/`.lnk` 启动时填显式进程名
- `exclude`：`'*.tmp'` 匹配任意层级文件；`'shadercache/'` 匹配任意层级目录；标记/锁/备份目录已内置排除
- `cover`：封面图路径（界面显示用，可选）

## 数据安全设计

- **中断保护**：只有推送成功才写 `云档.ok`。崩溃/断电/关窗口 → 下次缺标记 → 镜像模式拒绝直接覆盖（弹窗确认或降级时间戳）；归档模式检测“本地比最新归档新”并确认
- **误覆盖可回滚**：推送前网络端被覆盖/删除的文件先备份到 `云档备份/<时间戳>/`
- **并发保护**：网络锁防多机同时同步（可强制接管）；本机单实例防双开
- **锁的异常处理**：云档异常退出后锁会残留在共享目录——**同机重开时自动识别陈旧锁并清理（无需确认）**；其他机器接手时选“强制接管”，程序会重试删除（清只读属性），SMB 句柄延迟删不掉时自动把旧锁**改名让路**（不影响本次同步），仅当删除与改名都失败时才报错并给出手动处理指引（`.云档.lock`）
- 标记/锁/备份目录已从同步中排除，不会被镜像误删

## 常见问题

- **杀软误报**：PyInstaller 通病，加白名单；或用 `py 云档GUI.py` 跑脚本版
- **用 .lnk / 需要管理员权限的游戏**：引擎自动回退资源管理器方式启动（弹 UAC），此时请在编辑里填 `等待进程`
- **启动器常驻托盘导致一直等不到结束**：填 `等待进程` 为游戏本体 exe 名，或会话中点“提前结束并同步”
- **依赖**：Python 3.11+（3.10 需 `pip install tomli`）+ `psutil`（GUI 另需 `customtkinter`、`pillow`）
